Create An emptyDir Volume

05
LIFECYCLE EXPERIMENT

Investigate emptyDir Behaviour

After recreating the emptyDir Pod, /cache/message.txt was absent. The Pod was Running, but the test file was not there. This is a useful reminder to verify file creation before testing persistence.

kubectl exec day8-emptydir-pod -- ls -la /cache
Expected behaviour: deleting a Pod removes its emptyDir data. A replacement Pod gets a new emptyDir.

HOW IT FITS TOGETHER

Storage Architecture

Two separate Pods demonstrate two different storage lifecycles.

01 / TEMPORARY

emptyDir

Pod: day8-emptydir-pod
↓ mounts at /cache
emptyDir Volume

Shares storage with containers in the same Pod. Data survives a container restart while the Pod remains, but not Pod deletion.

02 / PERSISTENT

PVC-Based Storage

Pod: day8-storage-pod
↓ mounts at /data
PersistentVolumeClaim · 1Gi

Requests storage independently of the Pod. Data can remain available to replacement Pods when the volume and storage lifecycle support it.

Note: A PVC is a storage request, not a backup. Actual persistence depends on the backing volume, storage driver, reclaim policy and workload configuration.
